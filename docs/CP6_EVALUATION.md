# CP6 — версии, подтверждение и мониторинг

23 ноября 2026, Europe/Moscow. Технический сценарий пройден; закрытие владельцем и интегратором, а также утверждение контракта людьми не объявляются. Машинная сводка — [CP6_RESULTS.json](CP6_RESULTS.json).

## Реализовано

- Отдельный TradePlan из распознанных параметров последнего разбора. Черновик редактируется через HTTP с expected_version; сохранение увеличивает версию. Ответы чата не перезаписывают сохранённую форму автоматически.
- Серверный пересчёт через прежний Python/Decimal Risk Engine. Явные параметры формы являются пользовательским вводом; цифры и источник расчёта не принимаются на доверии из LLM или клиентского calculation. Обязательны капитал, количество, направление, стоп, лимит и проверенная спецификация. Проверяются валюта, лот, шаг, превышение лимита и экспирация.
- Подтверждение конкретной версии и SHA256 из ETag. Транзакция сохраняет snapshot, идемпотентный ответ и расписание мониторинга вместе. Конфликт → 409; неполнота или небезопасные параметры → 422. SQL triggers запрещают изменение/удаление snapshots.
- Правка confirmed создаёт следующий draft; worker продолжает проверять предыдущий snapshot до нового явного подтверждения. Повтор старого request_id возвращает первоначальное подтверждение.
- Встроенный worker читает только confirmed snapshot, без LLM. Он заново получает spec/quote через read-only sandbox, проверяет инструмент, свежесть, единицы, экспирацию и изменения спецификации. Источники с timestamps сохраняются в evidence; проверки содержат plan_version и source_ids.
- Сохраняемые уведомления по смене состояния правила, без повторов того же состояния после restart. UI подтверждает показ отдельным ACK; простое чтение списка уведомлений не меняет stored на delivered.
- UI: редактор, серверная карточка риска, проверка пользователем версии, статусы мониторинга и уведомления со ссылкой на источник. Несохранённая форма защищена от фонового обновления. Учебный стенд явно помечает моки.

## Политика данных и границы

Неучебное подтверждение требует настоящих свежих источников: спецификация до 86400 секунд, котировка в пределах самого строгого max_age_seconds автоматических правил (default 300, допустимо 1–3600). Будущие timestamps более чем на 5 секунд не считаются свежими. Последний отказ обновления не скрывается старым успешным источником. Источники и инструмент привязаны к собственному диалогу. Учебный план может явно сохранять старые/synthetic исходные источники, но worker всё равно требует свежую котировку для satisfied.

Проверяется условный убыток при исполнении у стопа, а не максимальный фактический убыток. Комиссии берутся только из явного поля; отсутствие издержек отражается в assumptions. ГО, доступные средства, другие позиции и маржин-колл не рассчитаны. Контракт плана поддерживает money и percent, но API требует капитал и валюту для контроля доли риска.

Автоматические правила MVP — только ценовые пороги. Ручное событие остаётся insufficient_data и требует человека. В frozen enum affected означает проверенный, но не достигнутый порог; это явно описано в contracts/README.md. История HTTP ограничена последними 100 checks/notifications; архив остаётся в SQLite, политика удержания ещё не реализована.

Один backend процесс и один общий демо-пользователь. Worker встроен в lifespan; SQLite lease на 120 секунд защищает отдельную проверку, но не превращает chat locks в многопроцессную координацию. Проверен штатный перезапуск; аварийный kill и восстановление защищённого backup на VPS относятся к CP7. Период проверки — best effort, без SLA; на план выполняются два сетевых чтения.

Уведомления только внутри приложения: delivered означает подтверждённый браузером показ, не прочтение и не отправку email/Telegram. Внешние каналы и отправка торговых заявок отсутствуют. При отключённом worker UI сообщает, что автоматические проверки отключены.
