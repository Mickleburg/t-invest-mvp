# CP5: технические критерии и сравнение провайдеров

Технический статус: **готов к закрытию по проверенному объёму**. Командное утверждение отдельно; агент не подменяет ревью владельца и интегратора. Машиночитаемые результаты и хеши исходных отчётов — [CP5_RESULTS.json](CP5_RESULTS.json).

## Что проверялось

Реальный PT Chat Completions, read-only T-Invest MCP sandbox, прежний Service/Risk Engine/SQLite и frontend. Учебные входы явно обозначены; источники реальные. API-ключи не передавались в промпты, UI или артефакты. Публичный DeepSeek и VPS в этот этап не входили.

В начале подтверждены base URL `https://api-llm.ptsecurity.com/v1` и запрос `model=deepseek`, без префикса pt/. Сервер сообщает `deepseek-ai/DeepSeek-V4.1-Flash`. Ранее temperature не отправлялась, default output limit был 2048, timeout 45 s, SDK retries отключены. GET /models вернул доступные имена; проверены deepseek, qwen35-122b-a10b, positive-llm-qwen36, positive-llm-code и отдельный локальный Codex.

Сначала сравнивались одинаковые учебные сообщения и сохранённый снимок источников: определение ГО, запрос до данных, запрос после данных. Эти snapshot-прогоны сравнивают модель, но не заменяют живую интеграцию. Затем выполнены свежие сквозные случаи: определение, три независимых диалога SiZ6, отсутствие стопа, неоднозначный BR. Для них каждый раз создавалось новое хранилище. Сетевые проверки отделены от pytest.

Финальные результаты живого набора (шесть случаев на профиль):

| Профиль | Результат | Медиана случая, с | Наблюдение |
| --- | --- | --- | --- |
| PT deepseek, temperature=0, enable_thinking=false, 2048 tokens | 6/6 | 4.133 | Основной профиль; три расчёта без повторного пользовательского запроса |
| PT qwen35-122b-a10b, те же настройки | 6/6 | 4.441 | Проверенная альтернатива |
| PT positive-llm-qwen36, те же настройки | 4/6 | 4.524 | Отказы проверки дословных цитат, в том числе неподтверждённая валюта стоимости пункта; ввод не принимался |
| local_codex, настоящий CLI provider | 6/6 | 19.830 | Схема Reply, реальные MCP/Decimal; режим разработки |
| Deepseek без отключения thinking, промежуточный промпт, 4096 tokens | 5/6 | 17.227 | Один ответ обрезался; это промежуточная диагностика, не финальный профиль |

Это измерения одного небольшого набора, не SLA или оценка вероятности успеха. Последняя строка относится к предыдущему промпту. Отдельный парный snapshot-тест **одного финального промпта**: deepseek с enable_thinking=false — 3/3 валидных Reply, медиана 2.617 s; без параметра — тоже 3/3, медиана 6.280 s. API принимает параметр; внутреннюю реализацию сервера мы не проверяли.

positive-llm-code в snapshot-тестах сообщает тот же response model ID, что deepseek; считать его доказанно отдельной моделью нельзя. Для positive-llm-qwen36 на одинаковом новом промпте отключение thinking изменило результат с 1/3 на 3/3 валидных JSON. Но валидный JSON не означает корректно распознанные финансовые параметры — поэтому финальный живой тест этой модели всё равно дал 4/6.

У исходного deepseek temperature=0 сама по себе не устранила двойной search и длинный текст: исходные ответы занимали 1099/1378/2263 символа. Исправление не сводится к выбору модели или увеличению token limit.

Codex проверен через установленный `codex-cli 0.171.0-alpha.13`, существующий local_codex → локальный MCP → structured CLI путь. Это реальные генерации с авторизацией CLI. Внутренняя модель CLI в этой трассе не сообщается; идентичность конкретной модели текущего чата не утверждается. Инструменты ОС/браузера у языкового subprocess отключены, брокерские/API токены из его env удалены. Для deployment CLI обязательной зависимостью не стал.

## Исправления поведения

- `agent/workflow.py`: для явно названного единственного фьючерса с запросом данных сервер выполняет search → spec → quote до генерации. Получение данных не зависит от того, сколько запасных поисков запросит модель. Класс и уникальность проверяются; неоднозначный выпуск не выбирается автоматически. Определение термина не запускает торговые инструменты.
- `agent/presentation.py`: арифметическая сводка риска, численные факты и ссылки формируются из Python-расчёта и полученных источников. Модель не пишет числа в эту сводку. Качественная часть ограничена по длине; численные/арифметические предложения отбрасываются, а не обрезаются посередине. Ограничения: reply ≤700, вопросы ≤140 каждый, видимый текст ≤1000 символов. Числа сохраняются в карточках и проверенных фактах.
- `agent/grounding.py`: если модель написала «пункты» вместо дословного «пунктов», можно заменить только цитату единицы на уже существующую точную цитату цены. Числа и значение валюты не меняются. Нет буквального подтверждения → отказ исходного Risk Engine.
- Свежий неудачный запрос спецификации не заменяется старой удачной спецификацией диалога. Пустой ответ quote не объявляется полученной ценой. При несовпадении ticker/classCode котировка не используется. Обновление относится к текущему запросу; обычное «спасибо» не повторяет рыночные вызовы. Нормализация валюты и лота отвергает неподходящие типы.
- Внутренние артефакты `provider-*.json` сохраняют requested/response model, temperature, token limit, thinking flag, finish_reason. `quality.json` показывает длину исходного текста и замену риск-сводки. Публичные DTO/OpenAPI/TradePlan schema не менялись.

Это программные границы поверх сменного провайдера; даже враждебный offline double с длинным ответом, выдуманными процентами или запасными поисками не меняет последовательность данных и не выводит свою арифметику пользователю.

## Критерии CP5 и доказательства

| Критерий | Доказательство |
| --- | --- |
| Настоящие модель, источники и HTTP/UI | Deepseek, Qwen35, Codex: по одному browser pass на desktop 1365 и mobile 390 px |
| Один полный запрос без дополнительного «теперь получи котировку» | Все три UI прогона: turns=1, model_calls=1, ровно search/spec/quote |
| Повторяемый выбор инструментов | По три свежих расчётных диалога для каждого принятого профиля; offline adversarial repeats |
| Риск вычисляется Python/Decimal | Бюджет 1000 RUB, два условных контракта дают 2000 RUB; spec_evidence_id относится к полученной спецификации |
| Нет лишней арифметики модели в тексте | Риск-сводка принадлежит серверу; тесты цифр, процентов, словесных вычислений и Plan/Fact полей |
| Краткость и образовательный вопрос | Ограничения длины на сервере; ГО без плана, risk_inputs и MCP |
| Ошибки/неполнота не превращаются в данные | Тесты failed search/spec/quote, missing stop, empty quote, неверного контракта/цитаты, повторного отказа свежего spec |
| Контракты и прежнее поведение не сломаны | 95 offline tests passed; check_contracts valid/no drift; frontend check; обе Compose config valid |

В браузере проверены превышение лимита, отсутствие JavaScript ошибок и горизонтального переполнения. Скриншоты и полные отчёты: `backend/runtime/cp5-eval/ui-deepseek`, `ui-qwen35`, `ui-codex`. В Git они не включаются. Новый `--once` штатно останавливает тестовый backend после ответа и удаляет созданную временную БД.

## Настройки и воспроизведение

Рекомендуемый локальный PT-профиль (ключ во внешнем env):

```env
LLM_PROVIDER=pt
LLM_BASE_URL=https://api-llm.ptsecurity.com/v1
LLM_MODEL=deepseek
LLM_TEMPERATURE=0
LLM_DISABLE_THINKING=1
LLM_MAX_OUTPUT_TOKENS=2048
LLM_TIMEOUT_SECONDS=45
LLM_ZERO_COST_CONFIRMED=1
LLM_INPUT_USD_PER_MILLION=0
LLM_OUTPUT_USD_PER_MILLION=0
```

Нулевой PT-тариф ранее прямо подтвердил пользователь. Call/token limits сохранены. Пустой LLM_DISABLE_THINKING выбирает проверенный default для PT deepseek/Qwen; 0 позволяет сравнить без этого параметра. Для публичного DeepSeek корпоративный параметр не отправляется. Qwen35 выбирается только сменой LLM_MODEL. Токены не записывать в пример окружения.

```powershell
# Живой acceptance основной конфигурации; каждый прогон использует свежие БД.
backend/.venv/Scripts/python -m backend.scripts.evaluate_cp5 --provider pt --model deepseek --zero-cost-pt --windows-user-key --output backend/runtime/cp5-eval/recheck-pt
# Codex как провайдер вместо PT API:
backend/.venv/Scripts/python -m backend.scripts.evaluate_cp5 --provider local_codex --output backend/runtime/cp5-eval/recheck-codex
# Сравнение моделей на одном сохранённом снимке, temperature=0:
backend/.venv/Scripts/python -m backend.scripts.compare_providers --output backend/runtime/cp5-eval/recheck-snapshots --temperature 0 --disable-thinking
```

Для browser smoke: `smoke_vertical_slice --zero-cost-pt --windows-user-key --once`, frontend с API_UPSTREAM=http://127.0.0.1:18003 и PORT=15173, затем `check_live_slice --output backend/runtime/cp5-eval/recheck-ui`. Для Codex заменить запуск backend на `smoke_vertical_slice --provider local_codex --once`. Каждая команда LLM — отдельный opt-in сетевой прогон; они не добавлены в offline pytest.

Остаются границы следующих этапов: не весь разговорный язык разбирается детерминированно; семантическая достоверность произвольного веб-исследования не доказана; это не нагрузочный или производственный тест. Версионированное подтверждение, worker, уведомления и VPS — CP6/CP7. CP5 готов к командному ревью по этим артефактам; согласование остальных provisional контрактов автоматически не происходит.
