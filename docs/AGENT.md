# Поведение агента и переходы

Спецификация provisional. Реализация: agent/service.py, models.py, prompt.py. workflow.py выделяет образовательный запрос и этапы данных для явного фьючерсного тикера; общий семантический роутер остаётся ограниченным.

| Намерение / этап | Действие | Переход |
| --- | --- | --- |
| Образовательный вопрос | Краткое объяснение, без обязательного плана/MCP | Если текущие данные не нужны, завершить ответ |
| Идея | Гипотеза, механизм, горизонт; максимум два необходимых вопроса | Пользователь выбрал конкретный инструмент и вопрос к данным |
| Данные | search → instrument_id → quote/spec/history/news; web для внешних оснований | Успешный источник с id/временем; ошибка остаётся неизвестностью |
| Разбор | За/против, различать факт и ожидание, evidence_id | Числа пользователя с цитатами; спецификация выбранного контракта |
| Риск | Service вызывает Python Risk Engine | calculated даёт карточку; unknown/over_budget ограничивают статус |
| Черновик | known/missing без выдуманных цен/сроков | CP6 создаёт TradePlan из распознанных полей; Reply.plan только сводка |
| Подтверждение | Пользователь проверяет форму и подтверждает version/hash | Сервер пересчитывает риск; worker читает immutable confirmed snapshot |

LLM получает инструкции, сообщения, ограниченный evidence и схему Reply; ключи/заголовки не передаются. Native tool calling/JSON schema mode не включены. Для проверенного PT включён JSON object mode; текстовый JSON валидируется локально. tool_requests — данные Reply с ограниченными kind; диспетчер выполняет только разрешённые операции. Торговых инструментов нет.

Service ограничивает раунды/повторные запросы. API-provider ограничивает вызовы, объём и расчётный резерв бюджета. Невалидный/усечённый ответ не запускает инструменты, не заменяется моками; ошибка сохраняется без provider error body.

Критерии: короткий reply, вопросы отдельно, без арифметики LLM и вымышленных событий/вероятностей, неопределённость при missing/сбоях. Наличие evidence_id не доказывает обоснованность факта; требуется независимая оценка.

Следующий шаг владельца 2: выделить intent/clarification/data/analysis/draft как тестируемые функции переходов, переиспользуя Service и инструменты. Golden cases: термин без плана; неоднозначный контракт; missing spec; недоступный источник; факт без evidence; prompt injection источника; попытка отыграться; несовпадение валют.

CP5 v3.1: workflow.py управляет данными; presentation.py ограничивает прозу и формирует расчётную сводку/факты из кода; grounding.py восстанавливает только подтверждённые цитаты единиц. Прошедшие критерии, сравнение PT/Codex и воспроизведение — CP5_EVALUATION.md. Старые указания ниже о следующем выделении этапов описывают исходный долг, частично закрытый этим изменением.
