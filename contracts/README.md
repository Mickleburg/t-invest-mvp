# Контракты API v0.2 / TradePlan v0.1

Статус provisional: технически зафиксированы, требуется ревью команды. Изменения согласуют интегратор 4 и потребители; агент не объявляет утверждение людьми состоявшимся.

openapi.yaml — OpenAPI 3.1, все операции генерируются из приложения и помечены implemented. В CP6 реализованы прежние planned маршруты истории, плана, подтверждения и мониторинга. Добавлены подтверждение показа уведомления (POST notifications/{notification_id}/ack), ETag плана и health.monitoring_enabled. Это реализация для ревью; командное согласование не объявляется. Reply.plan остаётся сводкой; отдельная сущность TradePlan хранится сервером.

trade_plan.schema.json — JSON Schema 2020-12, Decimal в строках, неполный draft допустим. Confirmed требует условия/параметры/расчёт/источники; фьючерс — стоимость пункта/валюту/лот/ссылку на спецификацию. Неучебный confirmed запрещает synthetic/stale/unknown источники. Схема не доказывает арифметику или истинность источника.

Сервер CP6 проверяет version/hash, принадлежность источников инструменту и диалогу, стоп/лотность/валюты/лимиты, шаг цены и экспирацию. Подтверждение атомарно и идемпотентно по request_id. PATCH заменяет переданные верхнеуровневые поля, увеличивает version и создаёт draft; прежний confirmed snapshot остаётся неизменным. Источники и расчёт назначаются сервером. После новой генерации чата сохранённый план автоматически не перезаписывается; правки выполняются в редакторе.

GET/PATCH плана возвращают ETag — SHA256 канонического черновика: JSON UTF-8, ensure_ascii=False, sort_keys=True, separators=(',', ':'), без confirmation, status='draft'. В confirm передаются 64 hex-символа без кавычек. Хеш покрывает показанную версию до смены статуса. Повтор того же request_id/версии/хеша возвращает прежний snapshot даже после правок нового draft; другое использование request_id → 409.

Check.status: satisfied — порог выполнен; affected — цена проверена, порог не достигнут; insufficient_data — нет подходящих свежих данных или событие ручное. Источник и время котировки доступны через source_ids в SessionState.evidence. Уведомления дедуплицируются по переходу состояния правила подтверждённой версии. stored означает запись; delivered — браузер подтвердил добавление уведомления в интерфейс, не прочтение человеком. failed зарезервирован для ошибки канала; внешнего канала доставки пока нет. В MonitoringState с not_started confirmed_version обозначает текущую кандидатную версию; подтверждённого снимка ещё нет.

examples/ — явно учебные моки. Пример confirmed не доказывает работу workflow. Внутренние интерфейсы: backend/app/interfaces.py и plans/monitoring/contracts.py. Нормализация всего evidence — CP1.

Из корня: `backend/.venv/Scripts/python -m backend.scripts.check_contracts`. Экспорт после согласования: `backend/.venv/Scripts/python -m backend.scripts.export_contracts`.
