# Правила разработки TradeGuard

Продукт помогает начинающим активным трейдерам разбирать идеи и контролировать риск, прежде всего по фьючерсам. Цель к Demo Day 5 декабря 2026: идея → уточнение → данные → программный риск → подтверждённый план → проверки → объяснимое уведомление. Удержание клиентов и снижение убытков пока гипотезы.

Сначала читать docs/BASELINE.md, ARCHITECTURE.md, OWNERSHIP.md, ROADMAP.md, локальный AGENTS.md и contracts/README.md.

- Единственная структура: frontend/, backend/, contracts/, infra/, docs/. По прямому решению пользователя старые приложения и эксперименты убраны из рабочей директории. Не восстанавливать их пакеты и дублирующие реализации.
- Один модульный FastAPI backend; frontend общается с ним по HTTP. AI, источники и арифметика разделены. Не вводить микросервисы/очереди без необходимости.
- Расчёты — Python/Decimal с явными единицами. Для фьючерсов нужна спецификация контракта; ГО не равно максимальному убытку. Не считать риск силами LLM.
- Не выдумывать данные, источники, события, вероятности и результаты вызовов. Нет данных → неопределённость. Моки явно помечать.
- Только read-only T-Invest MCP sandbox. Никаких заявок, реальных счетов и переводов. Токены не попадают в frontend, промпты, логи, артефакты или Git.
- Сначала изучать код, переиспользовать подходящее и делать минимальные изменения. Критическая бизнес-логика требует тестов. Не объявлять запланированные функции готовыми.
- Работать в своей ветке/worktree и зоне владения. Дополнительных coding-агентов запускать только по явному заданию. Чужие модули менять только при необходимости.
- Контракты меняются после согласования с интегратором и затронутыми владельцами. Статус provisional; агент не может объявлять командное утверждение состоявшимся.
- По прямому поручению пользователя агент делает содержательные коммиты после значимых проверенных изменений. Заголовки и описания новых коммитов — на русском языке. Author и committer — Git-идентичность пользователя, связанная с его GitHub-аккаунтом; без соавторства агента. Push, теги и Git init — только по отдельному поручению. Не копировать рабочие БД, секреты и venv в каталоги/архивы.
- Перед передачей: backend/tests, backend.scripts.check_contracts, frontend check. Сетевые и платные прогоны отделять от offline-проверок.

После работы сообщить изменения, затронутые файлы, результаты проверок, ограничения и нужные решения команды. Не объявлять чекпойнт завершённым без проверяемых результатов.

Актуальные результаты — docs/STATUS.md; независимые задания — docs/TEAM_TASKS.md; поведение агента — docs/AGENT.md. Нумерация CP0–CP7 и цель MVP до 1 декабря 2026 зафиксированы в docs/ROADMAP.md. Исторические отчёты не заменяют текущие результаты. PT ключ используется только локально; VPS — отдельный публичный DeepSeek ключ.
